Documentation

Install Molt, run the CLI, add your own tools, and keep it updated.

Install

DMG

Download Molt-macos.dmg, drag Molt into Applications, then open it. The DMG is universal (Apple Silicon and Intel) and requires macOS 14+.

One-line installer

curl -fsSL https://molt-site-five.vercel.app/install.sh | sh

The installer downloads the latest app and CLI, verifies SHA-256, installs the app to /Applications (or ~/Applications) and the CLI to /usr/local/bin (or ~/.local/bin), and removes the quarantine flag.

Homebrew

brew tap nichenqin/molt https://github.com/nichenqin/molt
brew install --cask molt-app
brew install molt

Homebrew installations should be updated with brew upgrade; Molt detects a Homebrew-managed CLI and says so instead of replacing it.

Signing status. Developer ID signing and Apple notarization are wired into the release workflow. They require an Apple Developer Program membership and are not yet enabled for the public build. If macOS blocks the first launch, right-click → Open, or run xattr -dr com.apple.quarantine /Applications/Molt.app.

CLI

molt                       # scan and list
molt list --json           # stable machine-readable snapshot
molt list --cached         # last snapshot, no network
molt list --source npm     # homebrew npm pnpm bun app cli mas custom
molt upgrade --all --yes
molt upgrade cc-switch --dry-run
molt changelog iina --limit 3
molt open sqlite
molt update --check        # check Molt itself
molt update                # replace the CLI atomically
molt doctor --json
molt cache path|size|clear
molt config path|init|show|edit

molt upgrade prints the exact argv it will run. Without --yes it asks once on a TTY and refuses in scripts. Download-only apps open their release page; Molt does not install them silently.

Custom tools

Edit ~/.config/molt/config.json. Partial documents are accepted:

{
  "disabledSources": ["mas"],
  "customTools": [
    {
      "name": "mytool",
      "path": "/usr/local/bin/mytool",
      "versionArgs": ["--version"],
      "versionRegex": "mytool (\\d+\\.\\d+\\.\\d+)",
      "github": "acme/mytool",
      "upgradeArgs": ["mytool", "self-update"]
    }
  ]
}

In upgradeArgs, the first element is replaced by the detected executable path and the rest is passed through. Omit it to make the row open the release page.

Updating Molt

Molt checks the static feed at https://molt-site-five.vercel.app/latest.json. When a newer version exists, the app shows an update banner; Molt → Check for Updates… opens the update sheet. The downloaded ZIP is verified against the feed's SHA-256, then a tiny helper waits for Molt to quit, swaps the app bundle with rollback, and relaunches it.

The CLI uses the same feed:

molt update --check
molt update

Homebrew users should run brew upgrade molt for the CLI and brew upgrade --cask molt-app for the app. The app also detects when it is running from a directory it cannot write to (for example a translocated quarantine path) and refuses to attempt a swap.

Security and limitations

  • No account, no analytics, no daemon, no sudo injection.
  • Upgrade plans are argv arrays; package names are never interpolated into a shell string.
  • Update downloads must be HTTPS and are checked against a SHA-256 from the feed.
  • Sparkle delta payloads are ignored; the full download is used.
  • Homebrew metadata is not auto-updated during a scan (HOMEBREW_NO_AUTO_UPDATE=1); run brew update if you want the latest formula metadata immediately.
  • Apps without a Sparkle feed, Homebrew cask, or explicit bundle-ID catalog entry are not guessed. Magpie uses com.yetone.magpie and yetone/magpie-releases; other apps can be declared as custom tools.

Build from source

git clone https://github.com/nichenqin/molt.git
cd molt
swift test
make app
make install

Requires Swift 6 and macOS 14+. The app and CLI share MoltCore; there is no daemon and no third-party runtime dependency.
