为什么是 Remige

不用在早餐前检查八个工具。

更新入口是碎的。Remige 并行运行原生数据源，去重合并，让每一行都有一个安全、明确的操作。

原生，不是又一个 Electron

SwiftUI 窗口 + 菜单栏，和 CLI 共用同一套核心。体积小、启动快，没有 Web 运行时。

安全的地方才一键

Homebrew、npm、pnpm、Bun、mas 调用各自官方升级命令。只有下载页的应用打开完整安装文件，绝不静默替换 App。

先看 Release Notes

GitHub Releases 与 Sparkle appcast 的更新日志会缓存，点更新前知道改了什么。

真正的 CLI

remige list --json、remige upgrade --all --dry-run、remige changelog iina。稳定 ID，脚本友好。

本地优先

无账号、无统计、无守护进程。上次扫描落盘，启动立即显示；单个来源失败不会清空整个列表。

不用插件运行时也能扩展

给 curl 安装的工具声明版本命令、GitHub 仓库和可选自更新命令，就够了。

常见问题

把话说清楚。

Remige 签名和公证了吗？

Release 由 GitHub Actions 构建并生成校验和。Developer ID 签名与 Apple 公证已接入发布流水线，但需要 Apple Developer Program 账号；在提供证书之前，macOS 可能显示 Gatekeeper 提示。安装脚本会移除 quarantine 标记。

会静默安装更新吗？

不会。Remige 调用包管理器自己的升级命令，CLI 会先显示完整 argv。非 cask 管理的 Sparkle 应用只打开完整下载页，绝不静默替换应用包。

需要 sudo 或账号吗？

不需要账号，也不会注入 sudo。brew cask 或 mas 需要提权时，会原样返回它们自己的错误。

没有 Sparkle 的 DMG 应用呢？

优先读取标准 Electron Builder app-update.yml（GitHub 或 HTTPS manifest），也支持按 bundle id 的目录项和 appUpdates 配置。都没有的应用会显示为未检查。Homebrew cask 管理的应用由 cask 来源负责。

有遥测吗？

没有统计、没有账号、没有后台守护进程。网络请求只发生在扫描所需的包管理器、registry、appcast 和 GitHub 页面。
