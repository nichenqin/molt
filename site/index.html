Why Remige

Stop checking eight tools before breakfast.

Updaters are fragmented. Remige runs the native sources in parallel, deduplicates the results, and gives every row a safe, visible next step.

Native, not another Electron app

A SwiftUI window and menu-bar item sharing one core with the CLI. Small binary, fast launch, no web runtime.

One-click where it is safe

Homebrew, npm, pnpm, Bun and mas run their own commands. Download-only apps open the full release, never a silent bundle swap.

Release notes, not guesswork

GitHub release notes and Sparkle appcast notes are fetched and cached, so you know what changed before you click.

A real CLI

remige list --json, remige upgrade --all --dry-run, remige changelog iina. Stable IDs for scripts.

Local-first by design

No account, no analytics, no daemon. The last scan is cached for instant paint; a failed source never blanks the list.

Extensible without a plugin runtime

Declare a curl-installed tool with a version command, a GitHub repo and an optional self-update command.

Coverage

Everything you actually install.

If a manager is not installed, its source is skipped automatically.

Questions

The honest details.

Is Remige signed and notarized?

Releases are built and checksummed on GitHub Actions. Developer ID signing and Apple notarization are wired into the release pipeline but require an Apple Developer Program membership; until those credentials are provided, macOS may show a Gatekeeper prompt. The installer clears the quarantine flag for you.

Does Remige install updates silently?

No. It runs the package manager's own upgrade command and shows the exact argv first in the CLI. Sparkle apps that are not cask-managed open the full download; Remige never replaces an app bundle behind your back.

Does it need sudo or an account?

No account. Remige never injects sudo. If a Homebrew cask or mas needs elevation, the tool reports its own error. Everything runs as your user.

What about apps installed from a DMG without Sparkle?

They are checked from standard Electron Builder manifests, a bundle-ID catalog entry, or an appUpdates config entry. Nothing is inferred from the display name. Apps managed by Homebrew are covered by the cask source.

Is there telemetry?

No analytics, no accounts, no background daemon. Network requests go only to the package managers, registries, appcast feeds and GitHub release pages needed for the scan.
